1 Getting started

FlowTex runs entirely in your browser. There's nothing to install on your machine; your administrator runs the server.

Signing up

  1. Open the FlowTex URL your administrator gave you. Click Create account.
  2. Enter your email, name, and a password (≥ 8 chars, with upper, lower, and a number). Passwords that have appeared in known breaches are rejected.
  3. Check your inbox for a verification link. The link expires in 24 hours; you can request a new one if needed.
  4. Sign in with your verified email and password.

Two-factor authentication Recommended

Open Account → Security and choose Set up 2FA. Scan the QR code with Google Authenticator, 1Password, Authy, or any TOTP app. Save the secret somewhere safe — you'll need it if you lose the device. Trusted-device cookies let you skip the code on familiar browsers for 7 days; the cookie rotates on every login so a stolen replica only works once.

Tip: Once 2FA is on, password resets keep working but invalidate every existing session — useful if you suspect your account was used elsewhere.

Filtering & sorting

The dashboard filter buttons cover All, Owned, Shared, Archived, and Trash. Click a tag to filter to it; click again to clear. Column headers sort the list. The search box matches project names instantly.

Bulk actions

Tick the checkboxes on the left to select multiple projects. The action bar appears at the top: archive, trash, tag, or untag them all at once.

Pending invitations

Invitations sent to your email appear at the top of the dashboard. Email links open you straight to the matching invitation — the link only works for the invited recipient. Read more about invitations.

3 Files & folders

The left-hand panel is your project's file tree. Files, folders, and binary assets live here.

Creating files and folders

  • Hit the + button in the file panel header and pick New File or New Folder.
  • Inside a folder, hover its row and click the small + to add a file directly into it.
  • Empty folders persist server-side — they survive refreshes and are visible to collaborators.

Drag & drop New

Drag any file or folder onto another folder to move it there. Drag onto the empty area outside any folder to move to top level. The target folder highlights blue while you're hovering. Name collisions are blocked before they happen — you'll get a warning, no overwrite.

Behind the scenes: A "move" is just a rename to a new path. Folder moves use a single atomic transaction so collaborators see the new tree consistently after one round-trip.

Uploading

Drag files from your desktop into the file panel to upload. Plain text files (.tex, .bib, .cls) are read into the editor; binary files (.pdf, .png, .jpg, .svg, fonts) are stored verbatim and rendered in a preview panel when opened.

Grouping & view modes

The toolbar at the top of the file panel switches between Tree view (folder structure) and Group by type (Source / Bibliography / Figures / Class & Style / Other). The list view shows the underlying paths regardless of how they're grouped.

Renaming, deleting, main file

Right-click any file or folder for its context menu: rename, delete, set as main file (compilation entry point), download, or format. Renames can include new directory prefixes — typing parts/intro.tex when renaming intro.tex moves it into parts/.

Downloading

File → Download as ZIP exports the entire project. Download for Submission resolves the dependency tree from your main file and only includes used files — handy for journals that reject unused assets.

4 The editor

FlowTex uses CodeMirror 6 with LaTeX syntax highlighting, autocompletion, bracket matching, and code folding.

Insert & Format menus

Bold, italic, underline, monospace, emphasis, highlight, inline/display math.

Interactive grid → properly formatted tabular code.

Autocomplete from labels and BibTeX keys in your project.

Auto-save

Your edits save automatically one second after you stop typing. Hit ⌘+S (or Ctrl+S) to flush immediately — this also triggers compile if you have that wired to save. There's no "unsaved changes" state: if you typed it, it's persisted.

Undo & redo

⌘+Z undoes; ⌘+⇧+Z redoes. History survives even after collaborators apply remote changes — your undo stack is yours alone.

Folding & navigation

Click the small triangle in the gutter next to environments (\begin{...}, \section) to fold their contents. ⌘+P (when wired in your build) opens a fuzzy file finder.

Multi-cursor

Hold ⌥ (Alt on Linux) and click to place additional cursors. ⌘+D selects the next match of the current word.

Theme & zoom

View → Zoom In/Out scales the editor font. The editor and PDF can be independently inverted (dark mode); your choice is remembered per browser.

The Visual Mode toolbar

While visual mode is on, a small floating toolbar lets you apply bold / italic / underline by selection. ⌘+B, ⌘+I, and ⌘+U wrap the selection with \textbf{}, \textit{}, and \underline{} respectively.

6 Compiling

The PDF button in the toolbar (or ⌘+S wired to compile) sends your project to the server's TeX Live installation and streams the log back as it runs.

What happens on compile

  1. Your editor flushes the latest content (and tracked-change marks) to the database.
  2. The server reads every file, optionally injects the \TCadd / \TCdel macros, and writes them to a per-user scratch directory.
  3. latexmk runs with the project's chosen engine (pdflatex, xelatex, or lualatex) plus bibliography passes (biber/bibtex) as needed.
  4. The log is streamed live; when the run finishes the PDF panel refreshes.

Compile log

The bottom panel shows the live stream of LaTeX output. Errors are highlighted; clicking an error with a file/line jumps the editor there. Overfull/underfull box warnings can be hidden via View → Overfull/Underfull Warnings.

SyncTeX

Double-click anywhere in the PDF preview to jump to that line in the source, and vice-versa. Available whenever your engine emits .synctex.gz (which all modern TeX Live engines do).

Linting

After every compile, FlowTex runs chktex (or lacheck for .bib) and inlines the warnings in the editor gutter. Switch between linters in Project Settings → Compiler.

Word count

Tools → Word Count runs texcount against the main file and reports words, equations, figures, and tables.

Stop & clean

The Stop button kills a running compile. Clean wipes the cached aux files when you want a fresh from-scratch run (useful after restructuring bibliographies or labels).

Rate limit: 15 compiles/minute per project, 30/minute per user across all projects. If you hit it you'll see a brief "too many compilations" message — wait a few seconds.

7 Search & replace

FlowTex has two search scopes: within file and across the whole project.

Find & replace in the current file

⌘+F opens the search panel. Supports plain text, case-sensitive, whole-word, and regex modes. Navigate matches with Enter / ⇧+Enter. Replace and replace-all are right next to the find input.

Global search

The magnifying glass at the top of the file panel searches every file in the project simultaneously. Matches are grouped by file; click any line to jump straight to it. All searching runs client-side over the in-memory file list — instantaneous, no server round-trip.

8 Collaboration

FlowTex is built for real-time collaboration. Every keystroke in a shared project propagates to other open editors over WebSocket within ~50 ms.

Inviting collaborators

  1. Open Share from the project menu.
  2. Enter the collaborator's email. They must already have a FlowTex account.
  3. Pick a role: editor (full write) or viewer (read-only). Owners can change roles later.
  4. They receive an email with a link that opens straight to the matching invitation. The link only works for the invited address; failed accept attempts by other accounts are audit-logged.

Live presence

The top-right corner shows avatars of every collaborator currently in the project. Each has a unique cursor color in the editor; their cursors and selections move in real time. A small "is typing…" indicator appears below their name when they're editing.

Chat

View → Chat opens a per-project chat panel. Messages persist server-side; new collaborators see the full history. Viewers can read but not post (per role table above). The panel shows date separators, per-author bubbles, and a live typing indicator while others are composing.

Hover any chat message and click the ☺ trigger to add an emoji reaction (👍 ❤️ 😄 🎉 🤔 👀 ✅ ❌). Reactions appear as small pills below the bubble and sync in real time. When the chat panel is closed and new messages arrive, the toolbar shows an unread badge.

Member list refreshes live

When somebody accepts an invitation or is removed by the owner, the avatar bar in the toolbar and the @-mention autocomplete update automatically — no page reload needed. The server pushes a members-update frame on every change and the client refetches the member list.

9 Comments

Double-click any text in the editor to attach a comment to that range. Threaded replies, @mentions, resolve, edit, delete — Word-style review in your LaTeX source.

Adding a comment

  1. Double-click the text you want to comment on. A bubble appears in the right-hand panel aligned with the editor line.
  2. Type your comment. Use @ to start a member mention; pick from the autocomplete.
  3. Press Enter to post, or ⇧+Enter for a newline. Mentioned users get an in-app notification (the bell badges up) and an emailed digest if they aren't online.

Replies, mentions, assignments

Click Reply in any bubble to thread under it. @-mentioning a member with the optional "assign" UI puts the comment on their action list. Resolve a thread (✓ button) to collapse it; resolved comments are kept for the record and viewable in the bottom-of-panel "Resolved" section.

Notifications (bell)

The bell icon in the toolbar shows the count of unread @-mentions across all your projects. Click it for a dropdown of recent mentions (up to 50, kept for 7 days after being seen); each entry shows the mentioner, the project, and a snippet. Clicking a mention from a different project switches you into that project; clicking one in the current project opens the comments panel. "Mark all read" clears the badge in one click. If you're offline (or the tab is closed) when somebody mentions you, a single digest email is sent within ~5 minutes covering everyone who mentioned you, across all your projects.

Emoji reactions on comments and replies

Hover any comment or reply and click the ☺ trigger that appears in the corner. Pick from a small palette: 👍 ❤️ 😄 🎉 🤔 👀 ✅ ❌. Reactions appear as pills under the comment — click a pill you've placed to remove it, or click someone else's pill to add yours alongside. Reactions sync in real time across all collaborators (server-authoritative: the server broadcasts the full reaction set after every toggle so every client converges).

Live alignment

Comment bubbles slide in lockstep with editor scroll — each card pins to its line. If two comments target nearby lines, an elastic packer gracefully spaces them so they don't overlap.

Tip: Comments survive remote edits. If a collaborator inserts text before a comment's anchor, the comment moves with the line — no orphaned bubbles.

10 Track changes

Word-style change tracking with per-author colors, accept/reject review, and an option to compile the PDF with insertions and deletions visible.

Turning it on

Click the TC toggle in the top toolbar to start tracking. With TC on, every insertion you make is highlighted blue (and underlined) and every deletion shows as strikethrough red. Other authors get their own colors; deletions are kept in the document (not removed from disk) so they can be reverted with a click.

The Review Changes panel

Toggle the side panel via View → Tracked Changes Panel. Each pending change becomes a card showing author, time, and a snippet of the inserted / deleted text. Cards align with the editor line they target and scroll with the document. Click a card to jump to it.

Accepting and rejecting

  • Per change: ✓ accept or ✕ reject inside each card.
  • Bulk: Accept all / Reject all buttons at the top of the panel.
  • Bottom review bar: When you're walking through changes one at a time, use prev/next arrows + accept/reject icons; the bar shows the current author and timestamp.

Show changes in the PDF

Enable View → Show Changes in PDF to compile a Word-style "All Markup" version. Insertions appear blue and underlined; deletions appear red and struck through. Toggle off to compile the final clean version.

Inline vs. data-only

If the inline color and strikethrough are too noisy while writing, switch off View → Show Tracked Changes Inline. The marks are still recorded — the panel and PDF still show them — they just stop coloring the editor.

Cross-author undo: If a collaborator deletes your tracked insertion (even with TC off) and then undoes it, your insertion is restored as an insertion — not as plain text.

11 History & snapshots

FlowTex captures a snapshot of every file on save and lets you browse, compare, and restore.

Browsing history

Open the History panel from the project menu. Snapshots are listed newest-first with author and timestamp. Click any to preview the file at that point.

Per-file diffs

Compare any two snapshots — or a snapshot against the current state — to see a side-by-side diff with inserted lines in green and deletions in red.

Compare-files PDF

Tools → Compare Files runs latexdiff between two states of the document and compiles a visually-marked-up PDF showing every change. Useful for reviewer responses.

Restoring a snapshot

From a snapshot's preview, click Restore. FlowTex first takes a "Before restore" snapshot of the current state (so the restore can itself be undone), then rewrites every file to match the target. A "Restored snapshot" entry is added to the history with your name and the original snapshot's id. The action is audit-logged.

Editors only: Viewers can browse history but cannot restore.

12 Bibliography

FlowTex supports both classic BibTeX and modern BibLaTeX / biber workflows.

Editing .bib files

Open any .bib file and the editor switches to BibTeX syntax highlighting. Tools → Format BibTeX rewrites the file with consistent indentation and alphabetical key order.

Citations & references

Insert → Citation inserts \cite{}. While inside the braces, your project's BibTeX keys autocomplete. Hovering a \cite{} or \ref{} in the editor opens a tooltip with the cited work's title, authors, and venue.

Complete Bibliography

Tools → Complete Bibliography scans your .tex files for cited keys and fetches matching records from CrossRef. Run it before submission to fill in missing entries.

CrossRef lookup

For ad-hoc lookups, paste a title or DOI into the bib enrich modal. FlowTex queries CrossRef and offers a properly-formatted BibTeX entry to insert.

13 GitHub sync

Link a project to a GitHub repository to push and pull your LaTeX source as commits.

Connect your account

Open Account → GitHub. You can either authorize via OAuth (recommended, one click) or paste a Personal Access Token with repo scope. The token is stored encrypted at rest with AES-256-GCM.

Linking a project

From a project, open Project Settings → GitHub and choose an existing repo or create a new one. Pick a default branch.

Pushing & pulling

  • Push: writes every file in the project to the repo as a commit. Supply a commit message in the prompt (CR characters are stripped to keep things tidy).
  • Pull: fetches the latest commit and overwrites local files. Local-only changes are lost — use it after you've pushed.
  • Auto-push: when enabled (Tools menu), FlowTex pushes every N seconds if anything changed.

Importing

From the dashboard, New → Import from GitHub. Pick a repo and branch; FlowTex clones the LaTeX files into a new project.

14 Zotero

Import your Zotero library directly as a .bib file.

  1. Open Account → Zotero and paste an API key from zotero.org/settings/keys. Keys must be alphanumeric.
  2. From any project, Tools → Zotero Import lists your collections.
  3. Pick a collection and FlowTex fetches it as a .bib file you can name and save into the project.

15 DOCX import

Convert a Microsoft Word document directly into a LaTeX project.

From the dashboard, New → Import DOCX. The converter handles paragraphs, headings, lists, tables, equations, figures, captions, footnotes, bibliography references, and embedded images. Pick a document class (article, book, report) and FlowTex emits a complete .tex project including media files.

Embedded images are converted server-side: SVG → PDF, GIF/TIFF/BMP → PNG, WMF/EMF → PDF via LibreOffice. Conversions you don't need can be disabled by your administrator.

Best-effort: Complex DOCX layouts (text boxes, columns, custom Word styles) may import imperfectly. Treat the output as a starting point and adjust.

16 Spellchecker

A Hunspell-powered spellchecker runs entirely in your browser. Pick a language from Tools → Language; the editor underlines unknown words.

Right-click a flagged word for the suggestion menu. Add to dictionary stores the word in your browser's custom dictionary so it won't be flagged again. The custom dictionary is per-browser, not per-account.

Toggle the entire spellchecker on or off with the toolbar button to the right of the language menu — useful for code-heavy documents.

17 Account & security

Profile

Open the user menu (top-right) and choose Account. From here you can change your display name, email (re-verification required), and password.

Password rules

  • ≥ 8 characters, including uppercase, lowercase, and a digit.
  • Checked against the Have-I-Been-Pwned breach database; passwords appearing in known breaches are rejected.
  • Resetting your password invalidates every existing session for the account.

2FA / TOTP

Set up a TOTP app (Authenticator, 1Password, Authy …). FlowTex enforces per-code replay protection — used codes can't be reused even within the same valid window. After enabling, a 7-day "trusted device" cookie lets you skip the second factor on familiar browsers; the cookie rotates on every login.

Trusted devices

You can revoke all trusted devices by disabling and re-enabling 2FA, or changing your password. Trusted-device creations are audit-logged with the device's user-agent.

Connected services

Account → GitHub and Account → Zotero manage external tokens. Revoking either deletes the encrypted token from the database.

Delete account

Permanent and irreversible. Owned projects without other members are deleted; shared projects survive but your authorship rows are anonymized.

18 Admin tools Admins only

If you have an admin account, the user menu shows an Admin Dashboard entry.

  • Overview: user, project, file, compile, and storage counts, with 7- and 30-day deltas.
  • Most Active Projects: top 20 by recent edits, with member / file / version / comment counts. An Owner column shows the project owner at a glance.
  • Users: list, search, view per-user activity (projects, edits, comments, chat, audit entries, recent logins).
  • Delete user: each user row has a Delete button that opens a triple-check modal — acknowledge the warning, type the target’s exact email, enter your admin password. Only when all three are satisfied is the destructive button enabled. The flow cleans the user’s authorship from comments / replies / versions, drops any project they alone own, audits the action as account_deleted_by_admin, and sends a goodbye email. Admins cannot delete themselves through this flow.
  • Audit log: every security-relevant event — logins, password changes, MFA changes, invitation accepts (and failed-by-mismatch attempts), snapshot restores, GitHub token issuance, and admin actions. Exportable as CSV.
  • SMTP / Email: test mail sending and rotate the admin SMTP password.
  • Compile metrics: live look at running compiles, queue depth, average duration.

Admin operations are themselves audit-logged.

About modal — which version is live?

Help › About shows a Build line with the short git SHA and build timestamp baked in at npm run build time. When FlowTex is deployed via scripts/provision-vps.sh, this is set automatically, so an operator opening About can confirm at a glance which commit is currently serving traffic. A development build (no git or missing env vars) shows dev.

20 Tips & gotchas

Compile button vs autosave: Clicking Compile flushes the editor's content and track-changes marks to the server first, so you don't have to wait for the 1-second autosave debounce. Hitting Compile mid-keystroke is always safe.
Stale bundle? If a feature seems missing after an update, your browser may be loading a cached JS bundle. Hard-refresh: ⌘+⇧+R (or Ctrl+⇧+R).
URL-typing into a project: Only your own projects are reachable via URL — typing someone else's project ID bounces you back to the dashboard. Every endpoint also checks server-side membership.
Long compiles: If a compile is stuck (looping \write18 or a slow package), use the Stop button. Compiles also auto-time-out at the server's configured limit.
Invitations: Invitation links are tied to the invited email address. Forwarding the email doesn't grant access to the new recipient — they'll see "this invitation isn't for your account" if they try.
Track changes & compiling with marks visible: The PDF wraps tracked text in \TCadd{…} / \TCdel{…} macros (with ulem underlining for inserts and strikethrough for deletes). Sectioning commands inside \TCadd can occasionally trip ulem's fragile-command rules; if you get a strange "scanning use of \@xdblarg" error, accept the change first or turn off "Show Changes in PDF" temporarily.
Empty folders: Folders you create are persisted server-side even before you put any file in them. They show up for collaborators in real time and survive refreshes.
